# UI/UX specification — «Мой график»

## 1. Визуальное направление

Интерфейс должен ощущаться как качественный VK Mini App:

- VKUI shell и системные паттерны;
- аккуратные карточки;
- спокойные акцентные цвета;
- минимум декоративного шума;
- без игрового визуала;
- без ощущения «сайта, вставленного во VK».

Функциональность важнее декоративности.

## 2. Адаптивность

### Mobile

- контент 100% доступной ширины;
- учёт safe area;
- основной сценарий рассчитан на управление одной рукой;
- bottom sheet для изменения дня;
- календарь помещается без горизонтального скролла.

### Desktop

- центральная колонка примерно 520–600 px;
- не растягивать календарь на всю ширину окна VK;
- визуально сохранять мобильную плотность интерфейса.

## 3. Темы

Поддержать:

- light;
- dark;
- системную тему VK/клиента, если доступна через integration layer.

Не хардкодить белый/чёрный фон там, где доступны semantic tokens VKUI.

## 4. Основные статусы

Статус всегда обозначается цветом + символом/текстом.

| Тип | Короткая метка | Визуальное направление |
|---|---|---|
| Дневная | `Д` | голубой |
| Ночная | `Н` | фиолетовый/индиго |
| Сутки | `24` | насыщенный синий |
| Выходной | `В` или нейтральная точка | нейтральный |
| Отпуск | иконка/`О` | зелёный |
| Больничный | иконка/`Б` | оранжевый |

Точные цвета задаются токенами темы, не фиксируются в продуктовой документации как абсолютные HEX до реализации.

## 5. Экран первого запуска

### Header

Название: `Мой график`

Подзаголовок в контенте:

**Как ты работаешь?**

Пояснение:

`Выбери график или настрой свой вариант.`

### Карточки пресетов

Сетка 2 колонки на mobile, если ширина позволяет.

Порядок:

1. `2 / 2`
2. `3 / 3`
3. `Сутки / трое`
4. `День · Ночь · 2 выходных`
5. `5 / 2`
6. `Свой цикл`

В каждой карточке:

- название;
- короткое описание;
- небольшая иконка;
- selected state.

### Дата начала

После выбора пресета показать:

`С какого числа начать?`

Контрол даты должен быть простым и нативно выглядящим.

### CTA

Основная кнопка:

`Построить график`

Disabled до валидной настройки.

## 6. Экран «Свой цикл»

Задача — дать собрать последовательность без сложного конструктора.

### Верх

`Свой цикл`

Пояснение:

`Добавь дни в том порядке, в котором они повторяются.`

### Текущий цикл

Горизонтальная/переносимая последовательность чипов:

```text
Д  Д  Н  Н  В  В  В  В
```

Каждый элемент можно удалить.

### Добавление

Кнопки:

- `+ Дневная`;
- `+ Ночная`;
- `+ Сутки`;
- `+ Выходной`.

Максимум 31 элемент.

Минимум 1 элемент.

### CTA

`Готово`

Возвращает на onboarding с выбранным custom cycle.

## 7. Главный экран

Главный экран не имеет нижней навигации.

### 7.1 Header

Слева/по центру — `Мой график` согласно VKUI pattern.

Справа — настройки.

### 7.2 Карточка «Сегодня»

Пример:

```text
Сегодня, 11 сентября
Рабочий день
08:00 — 20:00

Следующая смена 13 сентября · через 2 дня
```

Для выходного:

```text
Сегодня, 12 сентября
Выходной

Следующая смена завтра
```

Карточка должна быть визуально первой по иерархии, но не занимать половину экрана.

### 7.3 Календарь

Header:

```text
‹   Сентябрь 2026   ›
```

Дни недели:

```text
ПН ВТ СР ЧТ ПТ СБ ВС
```

Сетка 7 колонок.

Каждая дата содержит:

- число;
- короткий shift marker;
- today state;
- selected/tappable state.

Даты соседних месяцев либо не показываются, либо визуально сильно приглушены. Для MVP предпочтительнее пустые ячейки — меньше визуального шума.

### 7.4 Итоги месяца

Компактная карточка/группа:

```text
Сентябрь
15 смен    180 ч    15 выходных
```

Дополнительная строка при смешанном графике:

`8 дневных · 7 ночных`

### 7.5 Реклама

Sticky banner не должен визуально разрывать карточку календаря.

Рекламная зона располагается в безопасном месте после основного полезного контента либо через нативный VK placement, в зависимости от фактического рекламного API.

## 8. Карточка дня / bottom sheet

Открывается по тапу на дату.

Пример:

```text
19 сентября
По графику: Дневная смена

● Дневная      08:00–20:00
○ Ночная       20:00–08:00
○ Сутки        24 часа
○ Выходной
○ Отпуск
○ Больничный

Вернуть по графику
```

После выбора:

- изменение применяется сразу;
- sheet закрывается либо показывает короткий success state;
- календарь обновляется без reload.

## 9. Настройки

### График

- текущий пресет;
- `Изменить график`.

Изменение основного графика — потенциально разрушительное для существующих overrides. В MVP при замене графика показывать подтверждение и явно определить политику: overrides сохраняются только если совместимы по датам; предпочтительно оставить их, поскольку это абсолютные исключения по датам.

### Время смен

- Дневная: `08:00–20:00`;
- Ночная: `20:00–08:00`;
- Сутки: `08:00–08:00`.

### Данные

- `Сбросить график` — destructive;
- подтверждение обязательно.

### Приложение

- версия;
- ссылка на политику конфиденциальности/информацию, если требуется перед релизом.

## 10. Empty / loading / error states

### Initial loading

Короткий skeleton/spinner без искусственной задержки.

### Storage error

Календарь продолжает работать; показать ненавязчивое предупреждение, если сохранение не удалось.

### Fatal error

Понятный экран:

`Что-то пошло не так`

Кнопка:

`Попробовать снова`

При возможности — `Сбросить локальные данные` отдельным destructive действием.

## 11. Тексты

Стиль текста:

- простой;
- человеческий;
- без профессионального HR жаргона;
- короткие предложения;
- русский язык в первой версии.

Использовать `ты`, а не формальное обращение.

## 12. Motion

Только функциональная анимация:

- плавное появление sheet;
- короткое состояние selected;
- аккуратный переход между месяцами.

Никакой тяжёлой декоративной анимации.

## 13. UX acceptance

Сценарий нового пользователя:

```text
open → choose preset → choose date → build → calendar
```

Не более одного обязательного экрана настройки плюс системный date picker.

Сценарий повторного пользователя:

```text
open → current schedule visible
```

без дополнительных действий.
