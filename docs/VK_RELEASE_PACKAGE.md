# VK release package — «Мой график»

Актуально для VK App ID `54765581`.

## 1. Готовность к отправке

Кодовая часть готова к предрелизному деплою и подаче на модерацию после ручной проверки production URL на реальных устройствах.

Перед отправкой обязательно:

1. `npm install`
2. `npm run build`
3. `npm run deploy`
4. открыть production URL внутри VK на Android/iOS/desktop;
5. проверить onboarding, сохранение, настройки, back navigation, светлую и тёмную темы;
6. загрузить оформление и заполнить карточку приложения;
7. указать privacy/terms URL из этой же production-сборки;
8. отправить заявку на модерацию.

## 2. Тексты для кабинета VK

### Название

`Мой график`

### Краткое описание

`Календарь смен: выберите график и сразу увидьте рабочие и выходные дни.`

### Полное описание

> «Мой график» — простой календарь смен для тех, кто работает по циклическому графику.
>
> Выберите готовый режим 2/2, 3/3, 5/2, сутки/трое, день–ночь–2 выходных или соберите свой цикл. Укажите первый день графика — приложение автоматически рассчитает рабочие и выходные дни.
>
> В календаре можно посмотреть текущую и следующую смену, изменить тип отдельного дня, настроить время дневной, ночной и суточной смены и увидеть статистику за месяц.
>
> График сохраняется автоматически. Приложение поддерживает светлую и тёмную тему VK и работает на мобильных устройствах и компьютере.

### CTA / кнопка сниппета

`Открыть график`

### Разработчик

`Starcev Apps`

### Категория

Выбирать ближайшую доступную в текущем кабинете к `Инструменты / Полезные сервисы / Образ жизни`.

Не выбирать игры, развлечения, финансы или бизнес, если кабинет предлагает более точную утилитарную категорию.

```text

```

## 4. Сценарий проверки для модератора

1. Открыть приложение.
2. Выбрать `2 / 2`.
3. Указать первый день цикла.
4. Нажать `Построить график`.
5. Проверить календарь текущего месяца и статистику.
6. Открыть любой день и изменить тип смены.
7. Открыть настройки.
8. Изменить время одной из смен.
9. Вернуться назад.
10. Перезапустить приложение — график должен сохраниться.
11. Проверить light/dark theme при возможности.
12. Нажать `Сбросить график` — приложение возвращается к onboarding.

## 5. Оформление

Подготовить и загрузить:

- универсальная иконка — `576×576` PNG;
- иконка каталога/сниппетов — `278×278` PNG, если поле присутствует;
- маленькая иконка — `150×150` PNG, если поле присутствует;
- favicon — `32×32` PNG;
- большой сниппет — `1120×630` JPG/PNG;
- минимум 3 актуальных скриншота приложения; подготовленный набор — `600×1200`, единая вертикальная ориентация.

В новых формах кабинета универсальная иконка может автоматически использоваться для части меньших размеров. Отдельные файлы всё равно держим готовыми, потому что набор полей может отличаться по типу приложения/версии кабинета.

Рекомендуемый порядок скриншотов:

1. Главный календарь.
2. Настройки смен.
3. Первый запуск / выбор графика.

Скриншоты должны соответствовать текущей production-версии. После крупных UI-изменений их нужно переснять.

## 6. Privacy и пользовательское соглашение

В репозитории уже есть:

- `public/privacy.html`
- `public/terms.html`

Vite скопирует их в корень production-сборки.

После deploy получить базовый URL хостинга и проверить:

```text
<PRODUCTION_URL>/privacy.html
<PRODUCTION_URL>/terms.html
```

Эти URL можно указать в кабинете VK, если форма требует политику конфиденциальности/пользовательское соглашение.

Важно: если позже будет подключён внешний analytics endpoint или другой внешний обработчик данных, политику нужно обновить до включения такой обработки.

## 7. Deploy на VK Hosting

В проекте уже настроено:

- `homepage: "./"`;
- Vite `base: './'`;
- `vk-hosting-config.json` с App ID `54765581`;
- `static_path: dist`;
- endpoints `mobile`, `mvk`, `web` → `index.html`;
- `@vkontakte/vk-miniapps-deploy >= 1.0`;
- `predeploy` автоматически запускает production build.

### Первый deploy с компьютера

```bash
npm install
npm run deploy
```

Утилита сначала выполнит `npm run build`, затем попросит авторизовать размещение в VK, если локальной сессии ещё нет.

После успешной публикации сохранить выданный production URL и открыть его через карточку приложения VK.

### Если сломалась локальная авторизация deploy

```bash
rm ~/.config/configstore/@vkontakte/vk-miniapps-deploy.json
npm run deploy
```

На Windows удалить соответствующий configstore-файл пользователя вручную и запустить deploy снова.

### Автоматический deploy в CI — позже

Для CI официальный deploy package поддерживает `MINI_APPS_ACCESS_TOKEN`. Не добавлять токен в репозиторий; хранить только в GitHub Actions Secrets.
