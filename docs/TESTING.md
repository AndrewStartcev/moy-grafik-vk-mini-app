# QA protocol — «Мой график»

## 1. Automated gate

Перед каждой передачей на приёмку:

```bash
npm run typecheck
npm run lint
npm run test
npm run build
```

Все команды обязательны.

## 2. Schedule engine cases

### Presets

Проверить:

- `2/2`;
- `3/3`;
- `5/2`;
- `сутки/трое`;
- `день/ночь/2 выходных`;
- custom cycle.

### Направление по времени

Для каждого пресета:

- anchor date;
- +1 день;
- +полный цикл;
- -1 день;
- -полный цикл;
- дата сильно раньше anchor;
- дата сильно позже anchor.

### Calendar boundaries

- 28 февраля обычного года;
- 29 февраля високосного года;
- 1 марта;
- 30/31 числа;
- 31 декабря;
- 1 января.

### Shift duration

- 08:00–20:00 = 12;
- 20:00–08:00 = 12;
- 08:00–08:00 full day = 24;
- zero-work statuses = 0.

### Overrides

- базовый день → override;
- override → другой override;
- удалить override;
- override в прошлом;
- override в будущем;
- статистика учитывает override.

## 3. Onboarding manual test

- чистый storage;
- открывается первый запуск;
- каждый preset selectable;
- CTA disabled до валидных данных;
- дата начала выбирается;
- custom cycle нельзя сохранить пустым;
- custom cycle ограничен 31 элементом;
- после «Построить график» открывается календарь;
- после reload onboarding не появляется повторно.

## 4. Main calendar manual test

- открывается текущий месяц;
- today выделен;
- переключение назад/вперёд;
- правильные weekdays;
- начало месяца на любом weekday не ломает сетку;
- статус каждого дня совпадает с engine;
- card «Сегодня» совпадает с календарём;
- next shift корректна;
- monthly stats корректны.

## 5. Day sheet

- tap по дню открывает sheet;
- текущий resolved status выбран;
- выбрать day/night/full day/off/vacation/sick;
- календарь обновляется сразу;
- статистика обновляется;
- «Вернуть по графику» удаляет override.

## 6. Settings

- изменение времени смены;
- ночная смена через полночь;
- изменение основного графика;
- overrides после изменения графика ведут себя по согласованной политике;
- reset требует подтверждения;
- reset возвращает onboarding.

## 7. Storage

- reload сохраняет график;
- закрытие/повторное открытие сохраняет график;
- запуск вне VK использует localStorage;
- ошибка VK Storage не вызывает white screen;
- повреждённый JSON обрабатывается безопасно;
- неизвестная версия не ломает приложение.

## 8. VK environments

Минимум перед релизом:

- desktop VK;
- mobile VK Android;
- mobile/web viewport;
- light;
- dark;
- safe area;
- browser fallback.

Если iOS физически недоступен, это явно отмечается в release checklist как непроверенная среда, а не считается автоматически пройденной.

## 9. Ads

- нет рекламы в onboarding;
- banner не перекрывает UI;
- interstitial frequency cap;
- ad unavailable → UI продолжает работать;
- ad error → UI продолжает работать;
- повторное открытие не сбрасывает cooldown ошибочно.

## 10. Accessibility / usability

- touch targets удобны;
- статусы различаются без зависимости только от цвета;
- destructive actions подтверждаются;
- длинные названия месяцев не ломают layout;
- системное увеличение текста не делает приложение полностью неработоспособным.
