# AGENTS.md

## Роль исполнителя

Исполнитель отвечает за проект целиком: исследование, архитектуру, код, документацию, тесты, Git и исправления.

Андрей тестирует и согласовывает контрольные точки. Не перекладывать на владельца продукта разработку, настройку кода или техническое проектирование, если действие можно выполнить в репозитории самостоятельно.

## Главная цель

Сделать маленький, полезный и стабильный VK Mini App с коротким time-to-market и измеримой рекламной экономикой.

## Правила scope

Первый релиз должен оставаться MVP. Не добавлять без отдельного согласования:

- backend;
- регистрацию;
- AI;
- покупки;
- расчёт зарплаты;
- внешние календари;
- уведомления;
- несколько профилей;
- социальные функции.

## Архитектурные правила

1. Бизнес-логика календаря не зависит от VK Bridge, React и UI.
2. VK API инкапсулируется в `services/vk`.
3. Хранилище доступно через единый `StorageService`.
4. Реклама доступна только через `AdService`.
5. Аналитика доступна только через `AnalyticsService`.
6. Приложение должно работать в обычном браузере без VK через fallback/mock слой.
7. Расписание хранится как правило цикла + исключения, а не как массив рассчитанных дат.
8. Все сохраняемые данные имеют `version` и поддерживают миграции.
9. UI не должен напрямую вычислять календарную бизнес-логику.
10. Любая логика дат, влияющая на график, покрывается тестами.

## UX правила

- первый полезный результат — максимум за 60 секунд;
- после настройки приложение открывается сразу на календаре;
- никаких обязательных обучающих экранов;
- реклама не показывается до построения первого графика;
- переключение месяца и открытие дня не должны вызывать interstitial;
- статус смены обозначается не только цветом, но и символом/текстом;
- поддерживаются light/dark и mobile/desktop VK;
- интерфейс должен ощущаться как VK Mini App, а не отдельный сайт.

## Git

Основная ветка: `main`.

Формат коммитов:

- `docs: ...`
- `feat: ...`
- `fix: ...`
- `refactor: ...`
- `test: ...`
- `chore: ...`

Не использовать бессодержательные сообщения вроде `fix2`, `123`, `works`.

## Качество перед каждой контрольной точкой

Минимально:

```bash
npm run typecheck
npm run lint
npm run test
npm run build
```

Если одна из проверок не проходит, этап не отдаётся на приёмку.
